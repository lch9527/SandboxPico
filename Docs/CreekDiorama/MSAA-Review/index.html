拼车场景：关闭与 4× MSAA

2026-11-15 · 已合并主分支 cs210 · Unity 6000.3.21f1 · RTX 4060 Ti / D3D11 / Windows Editor。五关均在运行中的游戏场景拍摄。

Quest 尚未连接，因此没有本次真机 FPS 或 GPU 耗时结论。截图采集时主分支 Android / Mobile 默认是 2× MSAA，PC 是 4×；当时只临时改变测试实例。后续已按要求将 Mobile 和关联 Quality 档位改为 4×，配置及 Quest 构建入口使用同一 4× 设置。旧版写回 2× 的是生成／配置流程，并非每次普通 APK 构建都会重设。头显需重新打包安装后生效。

可见的改善集中在道路轮廓、招牌、轮胎和细线边缘。4× 后密集的小叶片仍有细碎轮廓，水面内部细节也不会因 MSAA 自动全部平滑。云的大片多边形明暗面属于模型/法线表现，不能把它们都当作像素锯齿。

MSAA 主要覆盖几何边缘，不能全面解决高光和纹理采样锯齿。程序纹样的 fwidth 过滤、纹理 mipmap、远处细小几何的 LOD 需要分别处理；本项目木材、石材及云的相关纹理已有 mipmap / Trilinear / 8× anisotropic 设置。Unity 官方说明

截图与验证方法

使用 Mobile URP 管线的临时克隆，1500×1000、render scale 1.0、FOV 70、相同 authored PlayerStart 与取景。后处理、深度图、Opaque Texture 均关闭。Camera.allowMSAA 为 true，管线与 RenderTexture 都明确设为 1 或 4 个采样；读回前 resolve。没有通过 Camera 的后处理 AA 下拉框冒充 MSAA。

计时与截图分开：每关四张截图在同一游戏帧内同步渲染，确保相机、角色位置与 shader 时间相同。关闭版重复截图完全一致；4× 重复版每 150 万像素有 75–155 个像素存在差异（不超过 0.011%），整体平均通道差低于 0.000063 / 255。这些差异远小于 OFF/4× 的差异，不将图片差分当作“锯齿减少百分比”。

PlayMode 自动验证通过，覆盖五关。未修改运行时美术 shader，也未将场景重新 bake。Quest 仍需在相同头部位置、分辨率、固定 foveation/sharpening、足够预热条件下再做实机 A/B。
